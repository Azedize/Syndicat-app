==================================================
SCENARIO 1 — ALI CREATES A NEW SYNDICATE
========================================

Ali lives in Tangier.

Ali owns an apartment in a residential building called:

Résidence Al Andalous.

The building contains:

* 3 blocks
* 60 apartments
* 8 shops
* Underground parking
* Common gardens

Ali and the other owners decide to create a syndicate.

Ali becomes the President of the syndicate.

He registers on the platform.

He creates the syndicate.

He enters:

* Building information
* Address
* Number of lots
* Number of owners
* Bank account information

The system automatically creates:

* Syndicate profile
* Default roles
* Buildings
* Lots structure

Ali starts a 14-day free trial.

SCENARIO 2 — FATIMA JOINS THE BUILDING
======================================

Fatima owns apartment A-205.

Apartment area:

95 m²

Floor:

2

Block:

A

The syndicate administrator assigns the apartment to Fatima.

Fatima receives an invitation.

She creates her account.

After login she can only see:

* Dashboard
* Payments
* Documents
* Complaints
* Meetings
* Voting
* Notifications

Fatima must NEVER see:

* Accounting
* Audit reports
* Payroll
* Maintenance budgets
* SaaS administration

==================================================
SCENARIO 3 — AHMED IS A TENANT
==============================

Ahmed rents apartment A-205 from Fatima.

Ahmed is not an owner.

Ahmed is a tenant.

Ahmed receives access to the platform.

Ahmed can:

* Download residence certificates
* Submit complaints
* Receive notifications
* View announcements

Ahmed cannot:

* Vote
* View budgets
* View financial reports
* View ownership documents

The application must enforce these restrictions automatically.

==================================================
SCENARIO 4 — TREASURER MONTHLY WORK
===================================

Every month the Treasurer logs in.

The Treasurer creates monthly charges.

Example:

Cleaning = 1,200 MAD

Electricity = 800 MAD

Security = 3,500 MAD

Gardening = 700 MAD

The platform calculates contributions automatically.

Invoices are generated automatically.

Payment reminders are sent automatically.

Dashboard KPIs update automatically.

No value should be manually calculated.

SCENARIO 7 — SUBSCRIPTION EXPIRATION
====================================

The syndicate subscription expires.

Ali receives notifications:

7 days before expiration.

3 days before expiration.

1 day before expiration.

After expiration:

The platform switches to READ ONLY mode.

Data remains accessible.

No data is deleted.

Users can still:

* Login
* Read documents
* View dashboards

Users cannot:

* Create documents
* Create meetings
* Create invoices
* Start new workflows

==================================================
SCENARIO 8 — SUPER ADMIN
========================

The Super Admin is not managing buildings.

The Super Admin is the SaaS owner.

The Super Admin manages:

* Subscriptions
* Plans
* Revenue
* Billing
* Organizations
* Platform health
* Security
* Storage
* Notifications

The Super Admin should NEVER manage:

* Parking
* Lots
* Complaints
* Maintenance
* Meetings
* Voting
* Residents

These belong to syndicates.
