==================================================
DOCUMENT GENERATION BUSINESS LOGIC
==================================

A member should never manually re-enter information that already exists in the system.

Example:

Ahmed is a member of Syndicat Zohor.

The database already contains:

* Ahmed full name
* Apartment number
* Building
* Phone number
* Email
* Syndicate name
* Syndicate address
* Syndicate registration information
* Syndicate logo

When Ahmed generates a document:

The system must automatically retrieve all available information.

Ahmed should only fill fields that do not already exist.

Example:

If generating a maintenance request:

The system automatically fills:

* Member name
* Syndicate name
* Building
* Lot number
* Date

Ahmed only writes:

* Problem description
* Additional comments
* Photos

This reduces errors and improves UX.

The Super Admin is NOT a document creator.

==================================================
NEW TEMPLATE REQUEST WORKFLOW
=============================

Business scenario:

A syndicate needs a new document template.

Example:

Syndicat A needs a new maintenance contract template.

Workflow:

Step 1

Syndicate Admin submits a request.

The request contains:

* Template title
* Category
* Purpose
* Description
* Expected fields
* Example document
* Images
* Attachments
* Legal references (optional)

Step 2

Support Team reviews the request.

Status:

Pending
Under Review
Accepted
Rejected
Need More Information

Step 3

If accepted:

Platform Admin creates the template.

Step 4

Template is tested.

Step 5

Template is published.

Step 6

The requesting syndicate receives a notification.
