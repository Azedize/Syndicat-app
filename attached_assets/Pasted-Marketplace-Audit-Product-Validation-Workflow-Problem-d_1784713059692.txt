Marketplace Audit – Product Validation Workflow

Problem detected:

The marketplace business logic has an approval workflow:

PENDING_REVIEW
→ APPROVED
→ REJECTED
→ NEEDS_CHANGES

However, the administrator currently has no visible moderation interface in the UI to manage products awaiting approval.

This creates a critical business issue because products can enter the validation workflow but administrators cannot efficiently process them.

Mission:

Perform a complete audit of the Marketplace moderation system.

Verify the following:

1. ADMIN VISIBILITY

Identify all administrator roles:

* Super Admin
* Syndicate Admin
* Marketplace Moderator

Check if they can access:

* Pending products
* Approved products
* Rejected products
* Products needing changes
* Reported products

If not visible in the UI, implement the missing screens.

---

2. MODERATION DASHBOARD

Create a dedicated Marketplace Moderation Dashboard.

Sections:

Pending Review

Rejected

Needs Changes

Approved

Reported

Reserved

Sold

Show counters for each section.

---

3. PRODUCT VALIDATION PAGE

For every pending product display:

* Product images
* Product title
* Category
* Brand
* Model
* Seller name
* Seller building
* Submission date
* Price
* Description

Administrator actions:

APPROVE

REJECT

REQUEST CHANGES

VIEW SELLER PROFILE

VIEW REPORTS

---

4. APPROVAL WORKFLOW

When admin clicks APPROVE:

Status changes to APPROVED.

Product becomes visible in Marketplace.

Notification sent to seller.

---

5. REJECTION WORKFLOW

When admin clicks REJECT:

Require rejection reason.

Examples:

* Inappropriate content
* Missing information
* Wrong category
* Duplicate listing
* Prohibited item

Notification sent to seller.

---

6. REQUEST CHANGES WORKFLOW

When admin clicks REQUEST CHANGES:

Require comment.

Status becomes NEEDS_CHANGES.

Seller receives notification.

Seller can edit and resubmit.

---

7. NOTIFICATION CENTER

Create notifications for:

Product Approved

Product Rejected

Changes Requested

Product Reported

Product Reserved

Product Sold

---

8. ROLE AUDIT

Verify:

Only administrators can moderate products.

Members and tenants must never see moderation tools.

---

9. UI AUDIT

If moderation APIs already exist but are not connected to the UI:

Connect them immediately.

Search entire codebase for:

pending_review
approved
rejected
needs_changes
reported

Identify every API endpoint that has no UI.

Create the missing UI screens.

---

Final Objective

No product should remain in pending_review without being visible to administrators.

Every moderation endpoint must have a corresponding UI.

Every administrator must have a complete moderation dashboard to validate products before publication.
